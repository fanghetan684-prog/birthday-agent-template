# 生日网站需求表

这份表用来减少来回提问，**不是必须填满的作业**。已经在聊天里说明的内容，Agent 应直接复用。空着的装饰细节可由 Agent 先做预览，真正缺少的关键信息再集中询问。

如果生日还没确定，不擅自写“今天”；没有年龄信息，不从照片猜年龄。昵称和生日相关信息以用户明确提供为准。

## 照片与主角标注

请用文件名或上传编号指定，不要求 Agent 跨照片认人。

| 文件名或编号 | 用途与分组 | 你的明确说明 |
| --- | --- | --- |
| `childhood.jpg`（示例名） | 开场童年照 | 是否加生日帽、是否保留原背景 |
| `portrait-01.jpg`（示例名） | 主角个人页 | 用户指定为主角照片 |
| `group-01.jpg`（示例名） | 某一回忆章节 | 保留完整合照，或明确指出要裁切的位置 |

以上只是填写示例，不代表仓库已存在这些照片。不要给同一文件重复起冲突的用途；不同版本可以保留独立副本。

## 回忆章节

每个章节可以用下面的结构描述：

```text
章节名：
属于这一篇的文件名或上传编号：
希望的照片顺序（不指定就由 Agent 编排并让我检查）：
已确认的地点或日期（不知道可以留空）：
这些照片对应的真实趣事（可选）：
这一篇想表达的一句话（可选）：
```

默认逐张翻看。照片应有前后按钮，手机可滑动；放大查看后返回原照片。不要为了填充页面编造具体故事，也不要给未标注的人物推断身份。

## 音乐（可选）

可以提供曲名与可用于本次作品的音频文件。不提供时可保留可关闭的音效，也可以全部静音。背景音乐必须可暂停，手机上按实际浏览器行为处理点击后播放；不要保证无操作自动播放。

## Agent 交付前核对

核对名字、年龄、主角素材指定、章节照片数量、真实信息与创作文案的边界；检查照片翻看、童年对话、蛋糕、礼物、可选密封信和签名流程。报告实际完成的验证，不把未测试的行为写成已通过。
