# 把一份回忆，做成可以亲手打开的生日礼物

这是一个交给 AI Agent 定制的生日网站模板。下载仓库，把照片和必要信息交给 Agent，它就可以沿着现成的结构制作：开箱惊喜、逐张翻看的相册、纸条蛋糕、童年照片互动，以及最后的礼物。

你不需要先学会编程。可以先看演示，再逐步替换素材；没有照片也能先制作演示，演示内容必须清楚标注。

## 最简单的使用方式

1. 下载并解压仓库，或克隆到自己的电脑。
2. 用支持本地文件和命令操作的 Agent 打开整个文件夹。
3. 把下面的提示词发给它，再上传你愿意用于生日页的照片。
4. 查看本地预览，修改文案与照片顺序。需要分享链接时，再让 Agent 按实际部署环境发布。

```text
请阅读本仓库 AGENTS.md 和 START-HERE.md，帮我制作生日网站。

先检查现有配置和素材，再问尚未提供的关键信息，不要重复询问。
我会提供寿星的称呼、生日或年龄、关系与语气、照片分组，以及想说的话。
主角照片由我按文件名或照片编号明确指定，请不要自行跨照片认人。

保留逐张翻看的相册、纸条拼蛋糕、童年照片点击对话和礼物解锁。
如果素材暂时不齐，先用清楚标注的演示素材完成预览，不要编造我们的回忆。
我需要看实际能点击的页面，请完成构建与相关检查，并明确报告哪些功能已经验证。
私人照片、正文、答案和密钥不要提交到公开仓库。需要收费时先告诉我具体服务和费用，等待我确认。
暂时先在本地制作；发布方式等我决定。
```

## 可以定制什么

- **开场惊喜**：当前提供可直接进入的生日开场；Agent 可按喜好扩展成开箱动画与金色大奖。
- **回忆相册**：当前为一个可配置相册，每次展示一张照片，支持上一张、下一张和手机滑动；Agent 可继续扩展旅行、聚会等章节。
- **童年对话**：点击童年照片，出现定制的短对话。只使用用户提供的事实或明确属于创作的祝福。
- **纸条蛋糕**：把几张祝福纸条逐步拼成蛋糕，再点亮或吹灭蜡烛。
- **特别礼物**：在约定的蛋糕完成阶段出现礼物入口，打开礼物图片或说明，再返回原来的生日流程。
- **可选加密信**：将私人正文密封为可部署的加密产物，不把明文和解锁答案放进公开配置。
- **真实签名墙**：由服务器接收和保存留言。多人看到同一批签名，需要部署带共享存储的后台。

当前默认签名表单为文字名字和祝福；服务器也支持笔迹数据，手写画布可由 Agent 按需补充。演示图是仓库原创 SVG，没有真实人物或第三方歌曲。

这些是模板的定制方向，不是对任意部署环境的保证。以当前代码、实际配置和测试结果为准。尤其要区分静态页面与服务器运行模式。

## 我需要准备什么

最重要的是：**称呼、关系和语气、生日或年龄、希望放进去的照片**。也可以补充章节名、祝福、音乐、礼物以及需要避开的内容。

为避免选错主角，请明确写出类似下面的说明：

```text
portrait-01.jpg、portrait-02.jpg 是我指定的寿星照片。
group-01.jpg 保留完整合照，不需要自动找出或裁切寿星。
childhood.jpg 用于开场大奖。
```

不用一次准备齐所有内容。Agent 应先利用已有信息继续工作，只询问真正影响下一步的缺项。完整素材清单见 [docs/BRIEF.md](docs/BRIEF.md)。

## 运行与构建

需要 Node.js 24。依赖是否需要安装，以 `package.json` 为准；首次运行可以执行 `npm install`。

```sh
npm run build
npm test
npm start
```

- `config.json` 是通用演示配置。制作个人站时，先复制为被忽略的 `config.local.json` 再编辑；构建脚本优先读取本地配置。
- `tools/build.mjs` 将配置生成到 `public/birthday/config.js`。
- `npm run build` 生成或更新页面需要的配置产物。
- `npm test` 执行仓库提供的检查；自动检查不替代浏览器中的手机操作验收。
- `npm start` 运行 `server.mjs`。以终端实际输出的地址打开网站，不假设某个固定端口。

只修改源码配置，不要只改生成后的 `config.js`，否则下次构建会覆盖修改。个人照片、音乐和礼物建议放在默认被忽略的 `public/birthday/assets/user/`；引用使用 `assets/user/` 下的相对路径。

### 可选：密封私人信件

将私人输入放到被忽略的 `private/card.json`，按脚本要求准备字段，然后执行：

```sh
node tools/seal-card.mjs private/card.json
```

它生成 `public/birthday/card-sealed.js`，用于部署。该产物默认也被 Git 忽略；公开模板不需要包含某个人的加密信。部署个人生日站时，由 Agent 核对并携带需要的产物。

不要凭猜测填写输入格式；先看脚本的参数说明与校验。不要把私人正文、解锁答案或服务密钥复制进 README、配置示例、构建日志和公开提交。

## 隐私与分享

公开模板仓库只放代码、通用说明和可公开使用的演示素材。你的私人照片、礼物卡、私人信件及生成的个人站产物不应直接提交到公开模板仓库。分享前还要检查 Git 已跟踪文件和历史记录：添加忽略规则不会自动移除过去提交过的文件。

网页发布后，浏览器需要加载的图片和音频通常能够被访问者获取。“隐藏入口”“未公开链接”和“图片没出现在首屏”都不是访问控制。礼物中含兑换码或其他不宜公开的信息时，应先处理可公开内容，再决定发布范围。

加密信是可选保护，不能把它宣传成绝对保密。解锁答案应足够难猜，具体保护能力取决于实现；它也不能替代服务器访问控制。

## 本地、静态与多人共享

| 运行方式 | 适合用途 | 签名与数据边界 |
| --- | --- | --- |
| 本地演示 | 自己预览、调文案与动画 | 不是已对外部署的网站；浏览器本地记录不会自动共享 |
| 静态托管 | 分享照片、动画、蛋糕与礼物流程 | 单独上传静态文件不会运行 Node 后台；不能声称具备真实共享签名墙 |
| Node 服务器 + 持久共享存储 | 朋友共同访问并留言 | 需要实际接通后台、验证保存，并说明部署与存储边界 |

部署说明见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。本模板不承诺网站已经部署，也不承诺任何平台永久免费。没有明确授权时，不创建付费资源或开启收费服务。
